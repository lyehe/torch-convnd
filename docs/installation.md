# Installation

Use Python 3.10+ and PyTorch 1.11+. Install the CPU/CUDA/ROCm distribution suited
to your environment before installing this package. The project's runtime
dependency is PyTorch; export and build tools are optional extras.

From a source checkout:

```sh
python -m pip install .
python -m pip install ".[native]"       # ninja, setuptools, packaging
python -m pip install ".[onnx]"         # onnx, onnxscript, onnxruntime
python -m pip install ".[legacy,onnx]"  # constrain NumPy for older framework wheels
```

For development, use `python -m pip install -e ".[dev,docs,onnx]"`. Production
consumers can install the wheel generated by `python -m build`:

```sh
python -m pip install /path/to/torch_convnd-0.5.0-py3-none-any.whl
```

Pin that wheel or a repository commit in the consuming project's dependency file:

```sh
python -m pip install "git+https://github.com/lyehe/torch-convnd.git"
```

The source repository is public; the package has not been published to PyPI.
The `legacy` extra supplies NumPy <2 for old PyTorch binary bridges. It does not
upgrade the installed framework or add a compiler requirement.

## Compiler-free use

`backend="torch"` never invokes the addon compiler. The automatic backend also
uses portable operations when a required native compiler, ninja or CUDA toolkit
is missing. Import and ONNX export require no native build.

```python
from torch_convnd import ConvNd

layer = ConvNd(2, 4, 3, dimensions=5, backend="torch")
```

## Native execution

Install a compiler compatible with PyTorch and the `native` extra. PyTorch's
builder selects its required C++ standard (newer releases can require C++20).
NVIDIA execution also needs a
CUDA toolkit with `nvcc` compatible with the installed PyTorch build; the CUDA
runtime bundled in a PyTorch wheel is not a compiler toolkit.

Native execution requires the custom-autograd/fake-kernel and unified autocast
APIs detected at runtime. They are absent in the older releases; use `auto` or
`torch` there. Native CPU training is checked from 2.4 onward. The CUDA mixed-GEMM
optimization also checks for FP32-output ATen overloads; older capable native
builds retain FP32 promotion instead.

Windows uses MSVC/Visual Studio Build Tools. The loader activates its compiler
environment when needed. Linux uses the configured C++ compiler. macOS CPU uses
Apple's command-line toolchain; hosted macOS verification is defined in CI and
has not been executed on this local Windows machine.

```python
from torch_convnd import load_native

load_native(with_cuda=False)  # explicit CPU build
# Use a fresh process for load_native(with_cuda=True).
```

Builds use PyTorch's extension cache with separate entries for source content,
installation paths, compiler settings and the PyTorch version. A new installation
or native source revision does not overwrite an older loaded library.
`MAX_JOBS` defaults to 2;
`TORCH_EXTENSIONS_DIR`, `CXX`, and `TORCH_CUDA_ARCH_LIST` configure the cache,
compiler and GPU targets. No platform binary is bundled in the Python wheel.
Configuration probes are cached for the process. Restart after changing build
tools or environment settings. An already loaded CPU-only addon cannot acquire
CUDA kernels in that process; automatic execution can still use the portable path.

An available toolchain can still fail to build because of version or system
configuration errors. Those errors are reported; kernel execution failures are
not swallowed. Use `backend="torch"` while diagnosing the native installation.

Default CUDA Inductor needs a matching Triton installation in addition to native
build prerequisites. Eager operation and `backend="aot_eager"` compilation do
not require Triton. The locally verified minimum stack uses PyTorch 2.10.0+cu130
and triton-windows 3.6.0.post26; consult the project's
[compatibility table](https://github.com/triton-lang/triton-windows#3-pytorch).

## Diagnostics

```sh
torch-convnd-info --json
```

The report includes versions, available runtimes, missing build prerequisites and
loaded-kernel state. It never compiles or allocates GPU tensors. Attach it with
the input/weight shapes, dtype, backend and complete error when reporting a problem.
